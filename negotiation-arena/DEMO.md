# Демо: один момент, два исхода

Цель: показать обязательные части ТЗ — настройку контекста, переговоры, обратную связь и зависимость результата от действий. Показывается живой интерфейс.

## Подготовка

- Mac: открыть `start-demo.command` из корня проекта. Windows/Linux: из папки проекта выполнить `node scripts/demo.mjs` (Node.js 22+).
- Открыть `http://127.0.0.1:5182/#arena` в Chrome. Сервер оставлять работающим.
- Эта репетиция использует отдельное хранилище. Основной профиль на 5177 не сбрасывается. Новый запуск репетиции создаёт новый профиль.
- Закрыть лишние окна показа, проверить масштаб и читаемость. Звук нужен только при показе мемного видео; основная ветка работает без звука.
- Ведёт мышь один участник. Другие участники объясняют происходящее.

## 1. Контекст тренера

Открыть `http://127.0.0.1:5182/#admin`. Обычный путь: База знаний → ссылка «Параметры тренировок» внизу.

Выбрать поставку. Исходные значения для воспроизводимого показа:

| Поле | Значение |
|---|---|
| Главная цель собеседника | Получить предоплату |
| Сложность | Практика (2) |
| Тон | Требовательный |
| Целевой день поставки | 10 |
| Бюджет, тыс. ₽ | 110 |
| Максимальная предоплата | 50% |

Для видимой настройки заменить тему на **«Поставка для демонстрации»**, нажать «Сохранить настройки». Перейти в «Тренировки» → «Просёр поставки». Оставить ресурс «Расширенный А.Н.А.Л.» и нажать «Начать П.Е.Р.Д.Ё.Ж.». Тема появится в чате; бюджет и срок — в ограничениях игрока.

## 2. Первая ветка — согласие с последствиями

Не активировать ресурс и не отправлять свободный текст в этой попытке: для маршрута нужны шесть определённых ходов.

| Ход | Кнопка / действие | Что объясняем |
|---|---|---|
| 1 | «Что вам реально нужно?» | Выясняем интерес поставщика |
| 2 | «Достать аргумент» | Обосновываем позицию |
| 3 | «Обменяться уступками» | Уступка предполагает встречный обмен |
| 4 | «Показать границы» | Называем предел своих обязательств |
| 5 | Цена **108**, день **10**, аванс **30**, две поставки **выключены** → «Предложить условия» | Проверяем конкретный пакет |
| 6 | «Подтвердить соглашение» | Осознанно принимаем показанный риск задержки |

Ожидается: соглашение; **100/100** за действия; финал **«Запахло последствиями»**; после задержки поставка на 12-й день, запас к целевому сроку **−2 дня**; **+120 XP**.

Фраза: «Технику переговоров оценили отдельно. Поставщик согласен, но наши обязательства не выдержали сбой».

## 3. Вторая ветка — меняем решающий ход

1. На результате нажать **«Изменить решающий ход»**. Откроется ветка перед ходом 5.
2. Сохранить цену **108** и аванс **30**.
3. Поставить день **8** и включить **«Две поставки: 60 + 40 комплектов»**.
4. «Предложить условия» → «Подтвердить соглашение».

Ожидается: соглашение; **100/100**; финал **«ПЕНИС в порядке»**; партии после задержки на днях **10 и 16**, обе границы соблюдены; **+140 XP**.

Открыть **«Сравнить продолжения»**. Объяснить: четыре начальных хода одинаковы, изменение начинается с предложения. Это сравнение решений в учебной задаче; повтор знакомого кейса сам по себе не доказывает рост навыка.

На чистом профиле две завершённые попытки дают **260 XP, ранг chad**. На основном профиле цифры другие из-за прежней истории. Прокачка даёт опыт за каждую завершённую ветку, а не за обновление страницы.

## 4. База знаний и мемы — если осталось время

- `#method/perd`: название, смысл букв, пример и «Попробовать».
- Отдельная новая поставка/проект → одно свободное сообщение. Первый такой ответ обязательно содержит одно из шести новых фото или короткий ролик; конкретное вложение случайное.
- Под ответом можно раскрыть «Условия сценария». Не называйте заготовленную шутку сгенерированной ИИ.
- `#knowledge/videos`: три примера «как не надо», у двух есть субтитры.
- «Не та вкладка»: средняя сложность → признать свою вкладку → спросить, что исправить → конкретный план → подтвердить. Это четыре хода и отдельная рубрика.

## 5. Дополнительное доказательство влияния настроек

Если жюри попросит: в кабинете тренера изменить бюджет с **110 на 100**, сохранить и запустить **новую** поставку. Бриф покажет 100; предложение на 108 будет нарушать бюджет. Повтор/ветка старой попытки сохраняет её исходные 110 — это намеренное поведение.

Эту дополнительную проверку делать после основного показа. Не менять бюджет посередине подготовки основной ветки.

## При сбое

Проверьте окно сервера и порт. Для нового чистого профиля остановите только сервер репетиции и запустите его снова. Основная история при этом не меняется. Если результат отличается, проверьте цель, сложность и все поля предложения. Для короткого показа можно заранее пройти обе ветки и открыть их сравнение, обозначив их ранее пройденными попытками. Отдельный деморолик не нужен.
